# Training Report Completer

一个用于补全大学实训报告、实验报告和课程实训 Word 模板的 Codex skill。优先使用老师提供的手册与附件，保留原件、表格结构和已有正确内容，按要求填写正文、步骤、心得，并处理必要的格式调整与真实截图。

**建议首次使用前，先在本机填写个人信息和课表，再让 Codex 与报告、手册交叉核验。核验有冲突时先解决相关字段，避免把错误姓名、学号、课程或日期写入报告。**

仓库仅提供通用规则、空白模板、脚本与合成测试，不附带真实个人资料或课表。

## 功能与适用范围

- 一次扫描报告及可选 DOCX 手册，定位正文、表格、嵌套表格、页眉页脚及截图占位。
- 基于结构化 patch 精确填写目标位置，保护原件、已有图片、签名图片及未修改区域。
- 新增普通文字可按规则使用小四字号；心得与教师评语正文支持首行缩进 2 字符。
- 按已核验的身份资料生成文件名，保留学号前导零，并清除文件名中的提示性加号。
- 在用户明确要求时处理真实研究和截图；未取得真实证据的项目保留占位并说明缺项。
- 教师评语与评分只在当前任务已有相应授权时填写，不伪造教师签名或实际批阅。

适用于已有 DOCX 模板的填写、已填写报告的纠错与身份转换，以及局部格式修复。普通论文写作、通用文档创作、独立网页研究和代码修改不属于本 skill 的主要用途。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 使用方式 | 支持加载 `SKILL.md` 的 Codex 环境 |
| Python | 3.10 或更新版本 |
| Python 依赖 | `lxml`、`python-docx`，见 `requirements.txt` |
| 视觉验收 | 当前环境可用的 DOCX 渲染工具；包内脚本不自带渲染器 |
| 真实网页截图 | 仅在任务要求时使用可访问目标站点的真实浏览器会话 |

## 安装

1. 下载发布 ZIP 并解压，或克隆仓库。
2. 将包含 `SKILL.md` 的文件夹命名为 `training-report-completer`，放入当前 Codex 的 skills 目录。常见默认位置为 `~/.codex/skills/`；自定义环境使用其对应目录。
3. 确认目录结构为 `skills/training-report-completer/SKILL.md`，避免多嵌套一层同名文件夹。
4. 在 skill 文件夹内安装依赖：

```sh
python -m pip install -r requirements.txt
```

如果环境已有可用依赖，可直接复用。

## 首次使用：先填写资料，再交叉核验

### 1. 在本机填写个人信息

复制 [个人信息模板](references/student-profile.template.md)，保存为同目录下的 `references/student-profile.md`。不要直接把真实资料填进已跟踪的模板文件。

模板包含以下空白字段：

```yaml
---
name: ""
student_id: ""
class: ""
major: ""
college: ""
school: ""
---
```

填写姓名、完整学号、班级、专业、学院、学校。建议准备常用字段；仅填写当前报告需要的信息也可以，未要求的字段不应写入报告。学号始终用引号包围的字符串保存，保留前导零；“学号最后两位”由完整学号提取。

### 2. 在本机填写课表

复制 [课表模板](references/timetable.template.md)，保存为 `references/timetable.local.md`。按当前学期的可靠资料填写：

- 适用学年、学期和资料来源；
- 课程全名或课程代码、任课教师；
- 报告需要时再填写星期、教学周范围、节次和地点；
- 需要把教学周换算为日期时，填写一个已确认的“日期—教学周—星期”基准，并记录调课或停课例外。

不要凭印象补齐不确定信息。课表可选；报告不需要课程、教师或排课信息时，缺少课表不阻塞正文填写。不要将其他学期的安排当作当前默认值。匹配规则见 [课表说明](references/timetable.md)。

### 3. 与报告和手册交叉核验

首次填写资料、更新学期或更换报告模板后，建议先发送：

> 使用 $training-report-completer。先核对我本机的个人信息和课表，并与这次报告、老师手册交叉验证。检查姓名、完整学号及末两位、班级、课程归属、教师、适用学期，以及有依据时的周次日期。只报告冲突和缺项，不在回复中重复展示完整个人资料。冲突字段先不要写入，其他内容可以继续。

| 核验项目 | 交叉核对方式 | 冲突或缺失时 |
| --- | --- | --- |
| 姓名、学号、班级 | 本机 profile 与当前报告已有身份字段比对；末两位从完整学号提取 | 填写模式暂停冲突字段；修改模式确认是原学生身份后按 profile 替换，不重复确认 |
| 课程归属 | 报告、手册与当前学期课表的课程全名或代码唯一匹配 | 不仅凭相似题目套用课程 |
| 教师 | 报告与手册中的明确教师信息优先，课表用于补缺，并注意实验教师可能不同 | 多个姓名冲突或角色不明确时保留该栏 |
| 教学周与日期 | 用已确认的日期、星期和周次基准换算，并核对调课安排 | 没有基准不猜开学日或实际实验日期 |
| 输出文件名 | 核对姓名、学号末两位、班级与报告内信息一致 | 依赖未知身份的正式命名暂缓 |

这里的交叉核验只验证已提供资料之间的一致性，不能证明原始资料本身真实。只有一份来源时应说明未能交叉核验，不联网搜集学生或教师的个人资料。现有会话中已确认的信息可以复用；有明确新指令时以新指令为准。

## 日常使用

准备报告 DOCX、可选的老师手册与附件，然后请求：

> 按这份实训手册补全已有 Word 报告。使用已核验的本机个人信息和当前学期课表，保留原件、表格结构和已有内容；需要真实截图的地方逐项完成，缺少的材料如实列出。

修改已有报告时可直接请求：

> 修改这份实训报告，把原学生信息换成我的；检查并纠正、补全学生应填写的步骤等内容，重新生成心得和普通教师评语。保留老师给定内容、真实批阅、表格结构及原件。教师栏目按本次已有授权处理。

这会进入修改模式；正文、表格、页眉页脚及文件名中的原学生身份均需核对替换，教师和文献作者等正常人名保留。非空内容修改仍需原文前置条件，不会全局替换所有同名词。确认属于他人的学生签名不能沿用为用户签名，也不会生成新签名。

仅修格式时可明确限定范围：

> 只修复这份报告表格的异常分页，其他内容和格式保持原样。

详细行为见 [SKILL.md](SKILL.md) 与 [填写规则](references/report-rules.md)。

## 脚本用法

以下命令从 skill 文件夹执行，文件路径需替换为实际位置；`work/` 目录需先创建。

```sh
python -X utf8 scripts/inspect_report.py report.docx manual.docx --output work/inspection.json
python -X utf8 scripts/apply_report.py report.docx work/patch.json
```

`manual.docx` 为可选参数。`patch.json` 由本次扫描结果和任务要求生成，目标 ID、原文前置条件及摘要不能照抄示例。patch 结构和可用操作见 [运行说明](references/local-environment.md)。

默认从本机 `references/student-profile.md` 读取资料；也可通过 `--profile` 指定资料文件，通过 `--output` 指定输出路径。输出不得覆盖原件。脚本返回的打开检查与结构检查不等于视觉验收。

## 隐私与安全上传

- 真实资料只写入本机 `student-profile.md`、`timetable.local.md` / `timetable.local.json` 或 `private/`；这些位置已加入 `.gitignore`。
- 真实报告、课表 PDF、截图、扫描结果、patch、缓存和历史工作目录均不应上传。
- 保留仓库中的模板为空；不要把真实身份、课表或本机绝对路径加入说明和测试。
- 提交前检查 `git status`、`git diff --cached` 和 `git diff --cached --name-only`；使用不含真实姓名、个人邮箱的 Git 提交身份。
- `.gitignore` 无法阻止 `git add -f`，也不会移除已跟踪文件。私有仓库同样需要脱敏。
- 如需反馈问题，请使用匿名化文字或合成文档，移除文档元数据、真实签名、个人资料和登录信息。

仓库归属仍会显示所使用的 GitHub 账户。更详细的范围说明见 [PRIVACY.md](PRIVACY.md)。
